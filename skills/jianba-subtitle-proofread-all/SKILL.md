# 剪吧全局字幕校对

通读当前全片最终字幕，只修正有依据的文字错误。以现有人工校正版为基线，保留样式、显式换行、分组、显示时间、原声和剪辑决定。全局任务在本 Skill 内处理话题分流，无需逐个加载话题校对 Skill。

用户要求实际校对时完成核实、文字修改与应用；明确“只检查、先给建议”时仅交清单。沿用已有授权，不为每个话题或批次重复确认。

## 范围与校对

通过当前客户端实际提供的剪吧 MCP 操作，短名只用于定位，参数以实时 Schema 为准。固定 `projectId`；“当前”可用 `get_editor_context` 的激活标签定位。缺连接或必要能力时说明具体缺项，不绕过应用改项目文件。

首次先读 `get_workflow_guide(workflow=subtitles)`，会话中已读且未变则复用。以 `get_subtitle_context` 的 `scopeId=all,source.kind=screen` 读取当前画面字幕。优先 `compact`；按真实 `cues.nextOffset` 续读并携同一 `subtitleContextKey`，有 `nextQuery` 时沿返回请求。全局发现须读完全部字幕，不能将首批或 summary 当全片。只有确需逐词声音时间才展开 `full`，不为格式变化重读。

按 [文字校对规则](references/proofreading.md) 集中判断，维护短清单：cue ID、有序 wordIds、原文、拟改文字、依据和疑点。只对疑点补听实际成片声音、查看相关原帧；配音项目核对当前配音，不对忽略的原声做 ASR。已有字幕缺失或来源过期时报告状态，不自动重建字幕覆盖人工内容。

读取 `screen.mode/scope/overrides` 和 cue 来源后，按 [继承与写回](references/inheritance.md) 选择保存位置：全片继承话题时，将已确认改字回写对应话题，保留继承；已有全片定制或无话题时，以当前全片 screen 做文字增量。对无法合法归属的余项保留并报告，不用全片快照悄悄替代继承。

## 保存与核对

每项修改仅提交 `{type:"update",cueId,text}`。省略 `settings`、`start/end`，不提交 `regroup`，不切换到自动字幕或清空已有选择。保留当前字幕语言及已有手工改写，只修改证实的错误。校对后若超出原分组容量或改变显式换行才能通过，保留该条并说明需要另行排版，不擅自缩字、拆组或改时间。

同一范围的文字修改按当前 Schema 上限成组保存，避免逐字写入。写入串行：每次保存后沿 `nextQuery` 读取当前文档绑定，后续批次使用同一 `source=document`，不能从 screen 新建另一份草稿丢掉上一批。应用前使用该文档最新上下文；读 revision、documentRevision 和 expectedVersion 各自独立。遇到版本冲突重读受影响内容并重新核实，不只替换版本号。

复用未变的原文页、术语清单和声画证据；写入每个范围前只重新取得必要绑定及候选所在页，核对 ID、有序词集与当前文字。其他话题写入会改变项目版本，不并行提交旧绑定；不因版本更新就反复通读全部未变内容。

对实际改字条目按当前文档请求 `preview_subtitle_video` 的 `cue_ids` 或 `scope_output` 时间窗口，分批核对全部改动的文字、换行、可读性与必要声音；相邻窗口合并，分散条目分窗。沿返回的 `waitQuery/readQuery` 等待和读取同一任务，复用匹配缓存，不固定短轮询或每改一句渲染整片。无法实际听看时保留未审阅草稿并报告缺项，不冒充已核对。

核对通过后按授权 `apply_subtitles_to_video` 应用同一文档快照，默认不请求整片渲染。应用成功后依新上下文检查实际 screen 文字及继承/覆盖关系。应用已成功而后续预览失败时，只处理预览失败，不重复写入。没有确认改动时不新建文档或应用。保留发布包及外挂字幕，保存/上屏不等于发布同步。

完成分别说明：已通读范围、实际改字、草稿/画面应用状态、局部声画覆盖、继承关系和未解决项。局部 `ready` 不能声称全片声画已验证；只有实际完整验证才如此报告。按返回状态结束本次审阅，已自动结束不重复调用，保留其他仍在使用的任务。
