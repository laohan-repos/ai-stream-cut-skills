# 全局校对的继承处理

本页用于决定改字应保存到哪个范围；文字修改仍遵守[主流程](../SKILL.md)的文字专用规则。全局首次从 `scopeId=all`、`source=screen` 分页读完实际画面字幕，以这一份内容发现错误并记录原文字、cue ID、有序 wordIds 和来源。不要再完整读取 automatic、inherited 或全部话题来重复校对。

先看全片 `screen.mode`、`screen.scope.inheritance` 和覆盖信息。处于话题继承时，全片是话题字幕按时间线映射后的结果；不能把改过文字的全片文档直接应用，因为这会建立全片快照，阻断后续话题继承。

继承模式下，用每条 cue 的 `provenance.scopeId` 将已发现的错误分配给真实话题。只读取有错误的话题当前 screen，以完全相同的有序 wordIds 核实对应 cue，并再次比较当前文字。对该话题真实 cue 保存文字增量，再应用文档；没有修改的话题不读取、不写入。全片展示时间可能与话题不同，不把全片时间复制回话题。

全片发现结果只是待核实建议，不是可跨范围直接提交的操作。话题当前文字若已经修正，就跳过；若有不同人工改写，只根据该话题当前文字修复证实的错误，不用全片整句替换。cue ID 必须取自实际写入范围，来源链只能说明上游，不能代替词 ID 对应。

继承字幕中 `provenance.scopeId=unassigned` 的内容没有可写回的话题归属。那里发现错误时，继续处理可可靠归属的话题，并报告仍未修改的具体字幕。这是当前工具的能力缺口，不能为修复它暗中创建全片覆盖、重置继承，或把有遗留错误的结果宣称为全部完成。归属缺失或不明也不能按时间邻近猜测。

没有话题、或全片已有覆盖时，以当前全片 screen 为完整基线，只保存证实错误的文字增量并应用全片文档。保留原有覆盖关系与其他人工内容；不要改为 inherited 或 automatic，也不要另行批量修改话题。此时应用全片文档只是延续既有全片基线，不代表话题轨道已同步。

阅读和判断可以并行，所有保存与应用必须串行。每次写入后沿返回查询取得新的来源绑定；保存后读取该文档再应用，不能把旧操作仅换版本号重试。其他话题或用户改动也会使绑定失效，冲突后重读相同来源、重新比较原文字。无需为了更新绑定再次校对所有已读内容。

最后用当前全片 screen 核实实际结果：继承模式应仍继承话题，已有覆盖应仍保留覆盖，修改只涉及确认的文字。保存草稿不等于上屏；预览或渲染结论依主流程据实报告，并列出因无归属或不可靠对应而尚未生效的部分。
