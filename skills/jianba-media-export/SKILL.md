# 剪吧基础导出

在应用设置目录或用户指定父目录下，由剪吧创建独立作品文件夹保存本次成果，保留现有剪辑、字幕、倍速与声画效果。普通“导出／导出视频／导出成片”默认将当前项目完整的剪后时间线导出为一条成片，显式使用 `target:{type:"project"}`，媒体参数沿用应用设置；“只要字幕”等明确请求只处理所选类别。明确的导出请求即授权完成该范围的导出，参数已清楚时直接执行。

## 绑定工具与目标

Codex 和 Claude Code 共用本流程。下文 `jianba:工具名` 指剪吧服务内的工具；首次从宿主工具目录绑定其实际全限定名，例如 `mcp__jianba__get_export_context`，随后复用。以实时 Schema 为准；首次进入导出工作流读取一次 `jianba:get_workflow_guide(workflow="export")`，同会话未变时沿用。

复用已明确的 `projectId`；不清楚当前项目时用 `jianba:get_editor_context` 的 active 项定位项目。新导出（含“再导出一份”）未明确指定范围时固定全片，不从界面选中话题、播放选区或上一轮单话题范围推断本次目标。只有用户明确说“当前话题／这个话题／指定话题”“指定组合”或“各自／分别导出”时才选择对应目标；选择多个话题（例如“导出1、3、4话题”）默认按所列顺序合成一条，不能使用会分别输出的 `target:topics`；只有明确说“分别／各自／每题一份”才逐题导出。“继续上次导出任务”按原任务记录恢复。组合、批量或明确范围仍有歧义时才读 [范围与物料](references/scopes.md)；只有仍影响交付的歧义才问用户一项。

只导出已保存内容。有未保存字幕或界面正在编辑时说明阻塞，保留用户修改。复用已有声画审阅；字幕过期、素材变化、目标不符或渲染异常时核对受影响部分，不为普通导出重新审阅全片。

## 读取准备摘要

按用户所选类别调用 `jianba:get_export_context`，默认 `detail=summary`：

| kind | 执行工具 |
| --- | --- |
| video | `jianba:export_video` |
| subtitles | `jianba:export_subtitles` |
| covers | `jianba:export_covers` |
| platforms | `jianba:export_platform_materials` |

保持目标、字幕来源、资源选择和覆盖设置一致。`directory/parentDirectory` 表示父目录，`outputFolder` 是只读计划；新请求不带 `exportFolderId`，应用在提交时创建以作品命名的文件夹，同名自动编号。目录、标题和编码未指定时省略覆盖，沿用应用设置；用户指定时，上下文放入 `overrides`，执行时放顶层。字幕 `source`、`coverIds`、`platformIds` 和平台 `format` 在两次调用都放顶层。视频画面字幕和独立字幕文件分别处理。

核对返回的实际目标、目录、准备情况和数量，记录 `expectedVersion/exportContextKey`。摘要足够就提交；缺项才读相关目标页或物料列表，`detailsOmitted` 不表示没有物料。无需为导出读完转写、字幕全文、无关类别或整套参考文件。已有请求参数和有效上下文直接复用，变化或冲突才刷新相关类别。

缺少所选物料时报告具体缺项，继续可独立完成的已授权导出。保留人工字幕与继承关系，按 [范围与物料](references/scopes.md) 核对来源；不通过重置字幕、翻译、生图、撰写文案或切换旧发布包补齐基础导出。

## 提交与等待

携匹配的 `expectedVersion/exportContextKey` 调用所选执行工具。每个实际导出请求保存一个稳定 `idempotencyKey`；传输重发复用原键，用户明确另导一份才新建请求。一次批量提交给应用排队。同次请求还要导字幕、封面或平台资料时，依次执行各类别，并在后续上下文和执行调用顶层都带首任务返回的 `exportFolderId`，使这些文件进入同一作品文件夹；不是每个类别各建一个文件夹。用户要求另导一份时创建新请求，不带旧文件夹 ID。

保存原始目标、类别、选择项、覆盖、绑定及 `jobId/exportFolderId/parentDirectory/directory`，更新同一份简短记录。用 `jianba:get_export_job` 默认摘要，按返回查询提示推进，长编码阶段适度延长间隔；不高频读取结果清单，不重复创建任务，也不用媒体预览等待工具查询导出。中断、取消、版本冲突或部分失败时读 [失败恢复](references/recovery.md)。

## 核对与交付

终态后用 `jianba:get_export_job(detail="results")` 沿 `items.nextOffset` 读完结果；每行至多一个文件，同一目标可以有多行。核对实际路径、目标、所选类别、文件数量/大小及返回的媒体时长，不能以摘要或 `progress=100` 代替结果。疑点才补做必要的局部声画核对，文件存在不代表已经观看。

只交付 MCP 返回的实际文件。最终位置应是应用设置或本次用户指定父目录下、由 MCP 创建并返回的作品文件夹；以任务 `directory` 和文件真实路径为准，不自行复制、移动、改名或拼装发布包。按所选类别验收，不要求固定语言、平台、封面数量、空占位目录或额外文件。平台资料中的素材引用不等于已复制素材。缺必要 MCP 能力时报告具体更新需求，不绕过应用导出。

`done` 且结果核对通过才报告全部完成；`partial/error/cancelled` 说明成功项、保留文件及未完成原因。简述实际位置、导出范围和必要疑点，避免复述整套上下文。旧任务查找、宿主名称差异或旧接口见 [宿主与兼容](references/compatibility.md)，仅在遇到时读取。
