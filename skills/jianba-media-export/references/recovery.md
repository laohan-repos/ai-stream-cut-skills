# 导出失败恢复

仅在中断、版本冲突、任务失败、取消或结果异常时读取。保留原请求的 projectId、target、kind、source、资源 ID、format、overrides、绑定、幂等键、exportFolderId、实际作品目录及各次 jobId；补充状态即可，不重贴所有文件或上下文。

| 当前事实 | 下一步 |
| --- | --- |
| 已取得 jobId，但连接中断 | 先查原 `get_export_job`，继续同任务 |
| 提交响应丢失，没有 jobId | 用完全相同参数和原 idempotencyKey 重发；相同请求复用原任务 |
| queued/running | 根据摘要查询提示等待；不新建任务、不重复读结果页 |
| 用户要求取消 | `cancel_export_job`；等待终态，当前编码阶段可能需结束，已写文件保留 |
| 编辑器有未保存字幕/正在编辑 | 说明需要用户先保存或处理当前操作，保留修改；不自动丢弃 |
| 内容或版本冲突 | 按原选择/覆盖刷新相关类别上下文，使用真实新绑定，不仅替换 expectedVersion |
| partial/error/cancelled | 先读完结果，核对成功与失败目标，再决定重试 |

## 重试范围

已授权导出遇到可恢复问题，可以在修正原因后进行一次有依据的重试；同因再次失败就报告具体阻塞，不无限重导出。素材或字幕需要另行修改且超出授权时先说明，不能为通过导出擅自改剪辑或人工内容。

`retry_export_job` 只接受终态原任务。用原始完整选择与覆盖、原任务返回的顶层 `exportFolderId` 读取新的 `get_export_context`，再传原 jobId、最新 expectedVersion/exportContextKey，以及本次重试的新稳定 idempotencyKey。返回的是新 jobId，记录父子关系并继续查询新任务。原初始请求的幂等键可能复用旧失败任务，不能拿它冒充重试。重试内部继承原文件夹，不向 retry 塞目录或文件夹 ID；新旧成功文件都留在原位置。

重试保留整个已成功目标，只重跑失败/取消目标，不是单文件断点续传。失败目标已写文件也保留，重跑可能生成编号文件，不能承诺没有重复文件。已有成功目标的内容变化时，应用会拒绝混用旧成片；说明需要新的完整导出，不只换 key 强交。

retry 不接受改目录、target、source、格式或资源选择。用户更改这些参数时，按新请求取上下文并使用新幂等键。用户明确要求再导一份也是新请求，未指定范围时使用全项目；只有明确“相同范围”才沿用原目标，不能复用旧成功任务冒充新增文件。

## 结果异常

终态用 `detail=results` 沿返回 nextOffset 读取，不用固定步长推算。根级 total 是目标数，items.total 是结果行数；同一目标的多个媒体文件会分行，失败目标也可有已写文件。

文件被移动、删除或校验不符时，任务可能转为 error/partial；以最新查询为准，保留仍有效结果，不自行搬回、改名或补文件制造成功。应用重启会将中断项标成失败，不假定自动续跑。结果页不可读取或缺失时说明尚未完成核验，不把摘要中的文件计数当作完整清单。
