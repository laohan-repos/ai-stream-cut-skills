# 剪吧话题字幕校对

只修正用户指定话题当前字幕中有依据的文字错误。以现有人工校正版为基线，保留其他话题、样式、显式换行、分组、时间、原声和剪辑决定。此 Skill 独立执行，不先运行全局校对。

用户要求实际校对时完成核实、文字修改与应用；明确“只检查、先给建议”时仅交清单。目标已明确便继续，不为每条修改重复确认。

## 定位与校对

使用当前客户端实际提供的剪吧 MCP 工具，短名只用于定位，参数以实时 Schema 为准。固定 `projectId` 和真实 `topicId`；“当前话题”结合激活标签的 scope、话题列表及用户原话定位，已有明确目标直接沿用。仍有影响结果的歧义才问必要的一项；不能把找不到话题当作全片任务，也不为校对新建或重分话题。

首次先读 `get_workflow_guide(workflow=subtitles)`，会话中已读且未变则复用。以 `get_subtitle_context` 的 `scopeId=topicId,source.kind=screen` 读取话题当前画面字幕。优先 `compact`，按真实 `cues.nextOffset` 续读并携同一 `subtitleContextKey`，有 `nextQuery` 时沿返回请求。读完目标话题，不扫描其他话题全文。确需逐词声音时间才展开 `full`，未返回字段仍未知。

按 [文字校对规则](references/proofreading.md) 集中判断，记录 cue ID、有序 wordIds、原文、拟改文字、依据与疑点。疑点才补听当前成片声音及相关画面；配音项目沿当前配音，不对忽略的原声做 ASR。未变的文字页、术语及已观察证据复用，不为换格式或修改一字重读整题。来源缺失或过期时报告具体状态，保留人工内容。

应用前读取或复用一次全片 `screen` 的来源/覆盖元数据，按 [继承与全片覆盖](references/inheritance.md) 判断实际生效位置。全片继承时让话题改字自然传递；有全片定制时，仅在可可靠映射且确有同一错误的目标全片条目上做文字增量。保留其他全片文字和覆盖，映射不清的余项报告未同步，不擅自恢复继承。

## 保存与验证

每项仅提交 `{type:"update",cueId,text}`；省略 `settings`、`start/end`，不用 `regroup`。保持当前语言及有意的人工改写，不用 ASR 重建已校对字幕。超出原分组容量、必须改变显式换行才能放下的条目保留并说明需要另行排版，不自动拆组、缩字号或改时间。

同一范围的修改按当前 Schema 上限成组保存。写入串行；保存后沿 `nextQuery` 读取当前文档绑定，后续批次使用同一 `source=document`，再应用当前修订快照。全片和话题是不同上下文，不能交换文档或 cue ID。每次成功写入后取得新绑定，复用未变证据及其余已读页；版本冲突重读受影响文字并重新核实，不只改 expectedVersion，不把读取 revision 当文档版本。

按实际改字条目用 `preview_subtitle_video` 的 `cue_ids` 或 `scope_output` 时间窗口，分批核对全部改动的文字、换行、可读性及必要声音；分散条目分别成窗，继承显示的全片坐标不能照抄话题秒数。沿 `waitQuery/readQuery` 读取同一任务并复用匹配缓存，不固定短轮询或为几句改字重渲染全片。无法实际听看时保留未审阅草稿并报告能力缺口。

核对通过后按授权 `apply_subtitles_to_video` 应用同一文档快照，默认不请求整题渲染。回读目标 screen 检查实际文字；必要时定向核对全片目标条目及继承/覆盖，不能只因话题写入成功就宣称全片上屏。其他话题文字、全部样式与排版保持。没有确认改动则不写入。画面字幕应用不改发布包或外挂字幕；应用已成功而预览失败时只处理预览，不重做成功写入。

完成说明真实话题、改字、草稿/画面状态、局部核对范围及未解决的映射/覆盖问题，不将本话题完成报告成全片完成。局部 `ready` 不等于整题已渲染验证。按返回状态结束本次审阅，已自动结束不重复调用，保留其他仍在审阅的任务。
