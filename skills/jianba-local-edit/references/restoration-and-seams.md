# 恢复、保护与接点取舍

恢复被删内容、遇到保护或字幕阻塞、修复吞字及突切时读取。以下是判断方式，不代表素材已有这些事实。

## 定向恢复

“补回那一句”先确认原片版本、准确表述和相邻内容。话题可用真实原始词 ID 的 `restorations` 或原片 `restore_ranges`，以 `canRestore` 判断；`editable=false` 不等于无法恢复。素材用其内部原片区间，不能借恢复改变当前话题选择。若内容本就未删，应检查倍速、当前播放范围或预览状态；校验草稿 `changed=false` 且需求已满足时直接说明，不再渲染、应用或宣称新增了内容。

恢复必须核对原片内容和成片衔接。话题恢复可能携带必要发音，使实际范围略宽于请求；素材时间边界不能切开已知 ASR 词。以草稿实际新增范围和预览确认，不承诺只增加请求文字的精确毫秒数。配音项目恢复画面时继续沿用配音，不恢复原片原声。

普通恢复不新增永久保护；用户明确要求“这句以后保留”才设 `protect=true`。省略 `protect` 沿用已有保护，`false` 仅解除该恢复接口建立的保护，不表示解除所有保护。

## 保护与历史

删除被保护的内容时，先确认保护来源及用户对该处修改的意图，不为通过校验批量解除保护。旧去重记录的保留词、手动保留和恢复保护可能并存；需修改历史去重关系时，按需读 `protections` 指南，通过真实记录的精确标识处理。遇到其他保护继续检查，不能把一次解除报告成全部解锁。

“恢复这一句”通过定向补回完成；“撤销刚才那次局部修改”则先确认当前相邻历史确属该目标与操作，再使用实时工具支持的专用撤销。后面已有其他编辑时，不跨过它们做全局回退，也不根据旧草稿覆盖当前状态。

## 吞字、突切与等待

听清原片及现成接点两侧，判断缺的是发音、完整词、必要画面还是上下文。补回最小必要内容，再核对新接点；不凭字幕假定被吞的是哪个音，也不靠任意增加停顿掩盖断裂。

话题新增逐词删除默认 `word_exact`；只有实际核对需要声音校正时，按当前 Schema 明确给出允许的前后扩展上限。声音校正用于新逐词删除，不能套到素材时间区间或自动重算历史切口。修复旧切口须按实际状态恢复并重新规划，避免同一方案恢复、删除重叠区间。

“这里等太久”把有效讲解、阅读、诊断与纯执行拆开。核实后删除无信息中段，保留启动、同次完成结果与因果。仅提高倍速仍可能留下长等待；按最终映射检查残留时长，同时检查多段短等待的累计拖沓。局部任务的检查范围由用户指出的问题及必要衔接决定。

## 字幕与确认

剪辑可能改变字幕时序或穿过人工分组。核对草稿的警告和实际预览；阻塞时说明需要调整的具体分组或对齐状态，按已有授权处理，缺少修改该内容的授权才询问。不可通过重置整套字幕来换取局部编辑成功，也不能把省略过期字幕的声画预览报告为字幕定稿。

局部预览窗口可因字幕重新分组或其他依赖扩大，按 `reviewWindows` 全部核对；后端无法安全局部化时会给出 `fallbackReason` 并回退完整素材预览。不要自行缩成只看切点。局部证明用于本次修改的声画核对，不能登记或报告成完整素材/全片预览。
